## Runtime surface decision

- No workspace implementation was lost in a Git worktree. The shared
  host/guest commits are contained by the current `vc-frame` donor branches.
- That surface is nevertheless not a finished product contract: its own guide
  calls it a manual vertical slice, and legacy sessions may still render their
  chrome inside the guest pane. Promoting it now would ship the duplicated
  Sessions rail and frame-inside-frame shown in the runtime screenshots.
- Version 4.1.0 therefore keeps the honest default: one ordinary operator
  `vc-frame` launched by `vc-start`. Host/guest remains deferred work, not a
  hidden second workspace mode.
- Live Runs is a projection of Vibecrafted Server `/api/control/state`. The
  observed `donor unavailable` state came from a configured server endpoint
  with no listener, while stale 3.7.1/4.0.1 processes were still visible.
  Product entry now checks status and, on macOS only, reconciles the single
  configured LaunchAgent instead of starting a second foreground server.
- The first notarized candidate exposed a separate packaging split: `vc-git`
  existed in source and installer tests but not in the mounted app. The builder
  now derives every missing Python launcher from the canonical
  `vibecrafted-core/pyproject.toml` script manifest, and the walk-around requires
  the isolated installed `vc-git --help` path.
- Resume-pack generation previously passed an ambiguous bare repository name to
  AICX. It now uses AICX's exact cross-organization `-p /repo` selector, which
  preserves aliases across organization renames while excluding similarly named
  sibling repositories. The unscoped all-project fallback was removed.
